# todo-board（看板 · 待办总览）

跨对话待办总览面板（slug：kan-ban-dai-ban-zong-lan）：把散在各对话
里的待决、进行与已办事项收在一块板上，按「在等谁」分三区。

## 主要功能

- 三区：「待你拍板」（按等待时长排序，带「已等 X 天」）、「进行中」
  （按下一节点日期升序，日期显示为人话标签）、「已办」（灰化紧凑，
  默认最近 5 条；超过 14 天由服务端自动清理）。
- 面板内可操作：待拍板事项带互斥选项按钮 +「其他想法」自由文本，
  点选即落库、转进行中并标「已拍板 · 待执行」；进行中可优先 /
  暂缓 / 取消（取消归档、不进已办）；已办可重新打开；已拍板未
  执行可「取消拍板」退回待拍板（留痕保留）。
- 执行发令与留痕：底部固定发令栏「完成，开始执行（待执行 N 件）」
  仅在待执行 > 0 时出现；每条事项带确认段 + 执行段两段留痕。
- 操作反馈：拍板成功有确认横幅并自动定位高亮卡片；失败显示具体
  原因并可原地重试；服务端动作日志记录每次点选/发令（含失败），
  供事后定位「点了没反应」类问题。
- 顶部三区计数即按钮，点击平滑滚动到对应区。

## 服务端动作

- `getBoard`：读取三区事项、待执行件数与发令时间。
- `addItem` / `updateItem`：新增 / 修改事项（写入纪律：进行中事项
  必须带节点日期或检查日期，无日期拒绝写入；暂缓项除外）。
- `actOnItem`：承接面板操作（拍板 decide / 优先 prioritize /
  暂缓 snooze / 取消 cancel / 重新打开 reopen / 取消拍板
  cancel_decision）。
- `requestExecution`：发令，记录发令时间（待执行归零时自动清除）。
- `getActionLog`：读取操作审计日志。
- `importInitialBacklog` / `backfillItemFields`：一次性导入 / 补全
  （幂等；仓库版内容已替换为虚构示例）。

## 数据说明

事项内容是运行时数据（标题、说明、拍板与执行记录等），只存在
线上运行时的 app.db，不入库；仓库内导入/补全动作的目标事项已
全部替换为虚构示例。

## 维护注意事项

- 执行闭环靠每 15 分钟的操作巡检：回读面板，接住「已拍板未执行」
  与「已优先」事项，按记录的决定执行并回写结果；无待办时静默。
- 入板分档：方案成形、只差拍板的立即入板；讨论阶段的提议满
  12 小时未响应才由漏记巡检补入；纯答疑不入板；待拍板满 7 天
  未拍板要在对话里提醒确认一次。
- 事项说明不写金额与敏感信息。
