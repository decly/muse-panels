# calendar-board（看板 · 事件日历）

事件的单一事实来源（slug：kan-ban-shi-jian-ri-li）：一期收录财报与
宏观日程，滚动展示未来 30 天，全部为北京时间墙钟时间。

## 主要功能

- 滚动窗口清单：过去 7 天 + 未来 30 天，按周分组（本周 / 下周 /
  更晚），过去事件保留 7 天并灰显。
- 两类事件：财报（earnings）与宏观（macro）；财报可关联持仓代码，
  重点事件（importance = key）突出显示。
- 财报日期未确认的条目标注「未确认」，核实后由维护方改 confirmed。
- 同一天内排序：盘前 → 无时间 → 定点发布 → 盘后，再按 sort、id。

## 服务端动作

- `getCalendar`：返回当前窗口（过去 7 天 + 未来 30 天，北京日期）
  内的全部事件，按日期与时段排序。
- `upsertEvent`：新建或更新一条事件（带 id 按 id 更新；否则按
  日期 + 类别 + 标题匹配更新，无匹配则插入）。
- `deleteEvent`：按 id 删除一条事件。
- `seedEvents`：仅在事件表为空时写入初始种子（归档版为虚构示例）。

## 数据说明

事件属运行时数据，只存在线上运行时的 app.db，不入库；面板自身
不抓取任何外部数据，全部条目由助手经服务端动作维护。仓库版种子
已替换为虚构示例事件（示例公司甲/乙财报 + 一条宏观示例），不含
任何真实财报日期与预期数字。

## 维护注意事项

- 核验节奏：每周六 09:00 持仓周汇总开头先核验未来 14 天事件
  （对照官方来源改期/补录），其下周展望直接读本日历；每日 06:30
  晨报的「近期注意」表也读 `getCalendar`（未来 7 天），发现已确认
  的缺失事件当场补录。
- 无预告发布日期的事项不录（如中国社融，央行不预告日期）。
- 二期范围（公司事件：除息、拆股、股东会）已原则同意、尚未建设；
  届时在本目录内扩展类别与动作。
